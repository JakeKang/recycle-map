# 09. QA와 장애 복구

## 릴리스 전 자동 검사

프로젝트 루트에서 다음을 실행합니다.

```bash
pnpm lint
pnpm test
pnpm test:e2e
pnpm build
pnpm security:audit
pnpm predeploy:check:full
```

`predeploy:check:full`은 개발·운영 환경 파일, 필수 마이그레이션, 운영 HTTPS와 비밀키 길이, 서비스 역할 키, 개발 우회 기능 비활성화를 검사합니다. 실제 값은 출력이나 문서에 복사하지 않습니다.

## 수동 핵심 시나리오

### 방문자

1. 홈이 열리고 목록·마커가 함께 표시되는지 확인합니다.
2. 검색과 모든 분류 필터를 바꾸고 URL 복원을 확인합니다.
3. 위치 상세의 상태·집계·리뷰가 보이는지 확인합니다.
4. 모바일에서 메뉴, 하단 탭, 상세 시트의 세 높이를 확인합니다.

### 로그인 사용자

1. 새 위치를 등록해 `확인 중`인지 확인합니다.
2. 50m 내 같은 분류 중복이 409 안내로 막히는지 확인합니다.
3. 타인 위치에서 한 표를 주고 선택을 바꿔도 총 한 표만 유지되는지 확인합니다.
4. 자신의 위치에서는 투표가 막히는지 확인합니다.
5. 리뷰, 신고, 수정 제안의 성공 안내와 갱신 결과를 확인합니다.
6. 내 제보를 수정한 뒤 투표와 상태가 초기화되는지 확인합니다.

### 관리자

1. 대기 신고를 해결·기각합니다.
2. 대기 제안을 적용·기각합니다.
3. 위치의 검증 상태를 수동 조정하고 사용자 화면의 표시를 확인합니다.
4. 비관리자 계정으로 `/admin` 접근이 차단되는지 확인합니다.

## 장애별 복구

| 증상 | 1차 확인 | 복구 |
| --- | --- | --- |
| 목록·상세 조회 실패 | 네트워크와 API 응답 상태 | 화면의 `다시 시도`, 반복 시 서버 로그와 Supabase 상태 확인 |
| 지도만 비어 있음 | 타일 URL·저작권 문자열·네트워크 | 목록 기능을 유지한 채 타일 제공자 설정 복구 후 새로고침 |
| 로그인 반복 실패 | 제공자 키, callback URL, 세션 쿠키 | 다른 브라우저에서 재현 후 NextAuth 서버 로그 확인 |
| 등록이 409 | 같은 분류의 50m 내 기존 위치 | 기존 위치를 사용하거나 좌표·분류 오류를 바로잡기 |
| 등록이 429 | 일일 5건 또는 분당 요청 제한 | 안내 시간만큼 기다리고 단일 요청으로 재시도 |
| 투표 불가 | 로그인·작성자 본인 여부 | 다른 사용자 위치에서 시도, 세션 만료 시 재로그인 |
| 저장 후 확인 중 | 위치 수정으로 검증 초기화됨 | 정상 동작이며 다시 시민 검증 진행 |
| 운영 DB 쓰기 실패 | 서비스 역할 키와 마이그레이션 | `SUPABASE_SERVICE_ROLE_KEY`와 최신 SQL 적용 확인 |
| 사진 업로드 실패 | 형식·크기·저장 디렉터리 권한 | JPEG/PNG/WebP 5MB 이하로 재선택, 서버 디렉터리 확인 |

## 복구 시 금지 사항

- 운영에서 `ALLOW_DB_FALLBACK_ON_ERROR=true`로 오류를 숨기지 않습니다.
- 브라우저에 `SUPABASE_SERVICE_ROLE_KEY`를 노출하지 않습니다.
- 오류가 난 제출 버튼을 반복 클릭하지 않습니다.
- 데이터 불일치를 확인하기 전에 관리자 상태를 임의로 덮어쓰지 않습니다.

## 증거 수집

문제 보고에는 민감 정보를 제외하고 발생 시각과 시간대, 페이지 URL, 사용자 역할, 대상 위치 ID, 예상·실제 결과, 재현 단계, 화면 캡처, 관련 서버 응답 상태를 포함합니다.
